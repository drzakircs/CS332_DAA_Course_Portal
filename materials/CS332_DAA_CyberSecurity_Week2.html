Session 4

Loop Invariants

A loop invariant is the truth that stays true as a loop progresses.

InitializationMaintenanceTermination
Motivation: “A loop may run many times. How do we prove it always moves toward the correct result?”
Bridge from Week 1

From correctness contract to loop invariant

📋
Pre-conditionTrue before algorithm starts
→
🔁
Loop InvariantTrue before every loop iteration
→
✅
Post-conditionTrue when algorithm terminates

Teaching sentence: An invariant is the “logical bridge” between the starting condition and the final result.

Say: “A loop invariant is not extra theory; it is how we keep the correctness contract alive while the loop is running.”
Core definition

What is a loop invariant?

A loop invariant is a statement that is true before the first iteration and remains true before every subsequent iteration.

At termination, it helps prove the desired result.

In simple words

It is the stable logical property that the loop preserves while processing more input.

Cyber example: after processing the first k log entries, the current count equals the number of suspicious entries among those k entries.

The invariant proof pattern

Three things to prove

1️⃣
InitializationThe invariant is true before the loop starts.
→
2️⃣
MaintenanceIf true before an iteration, it remains true after that iteration.
→
3️⃣
TerminationWhen the loop ends, the invariant gives the post-condition.

Invariant State

This example is simpler than sorting and prepares students to understand “processed prefix” in MAX and Insertion Sort.
Worked example

Loop invariant for MAX-RISK

MAX-RISK(A) max ← A[0] for i ← 1 to n-1: if A[i] > max: max ← A[i] return max

Invariant

Before each iteration with index i, max is the largest value in A[0..i−1].

Post-condition

When the loop finishes, max is the largest value in the entire array.

Common mistakes

What makes an invariant weak?

Mistake 1
The statement is true, but too weak.
↻
Fix
A weak invariant may not prove the post-condition. It must connect to the final goal.
↻
Mistake 2
The statement is only true at the end.
↻
Fix
An invariant must be true before each iteration, not only after the loop completes.
↻
Mistake 3
The statement ignores loop progress.
↻
Fix
A good invariant usually describes the processed part of the input and what is known about it.
↻

Session checkpoint

Loop invariant proof template

1
State the invariant clearly.
It must describe what is true during the loop.
2
Prove initialization.
Show it is true before the first iteration.
3
Prove maintenance.
Assume it is true before one iteration and prove it remains true after.
4
Use termination.
When the loop ends, combine the invariant with the stopping condition to prove the post-condition.
Session 5

Insertion Sort and Correctness

A simple sorting algorithm that is ideal for learning dry runs, invariants, and initial complexity analysis.

Transition: “Now we apply invariants to a full algorithm, not only a simple maximum loop.”
Intuition first

How insertion sort thinks

🃏

Cards analogy

Keep the left side sorted, take the next card, and insert it into the correct position.

⬅️

Shift larger items

Move larger elements one position right to make room for the key.

✅

Grow sorted prefix

After each outer iteration, one more element belongs to the sorted prefix.

Visual intuition

Insertion Sort behaves like arranging cards in hand

Sorted hand
245
Already arranged
+
New card
3
Insert into correct place
→
Updated hand
2345
Sorted prefix grows
Ask Students
What part of the array is guaranteed sorted during Insertion Sort?
↻
Suggested Answer
The prefix before the current key. At each outer-loop step, Insertion Sort grows this sorted prefix by inserting one new element into its correct position.
↻
This card-hand analogy should be used only to introduce intuition. Immediately connect it back to the sorted-prefix invariant.
Algorithm representation

Insertion Sort pseudocode

INSERTION-SORT(A) for j ← 1 to n-1: key ← A[j] i ← j - 1 while i ≥ 0 and A[i] > key: A[i+1] ← A[i] i ← i - 1 A[i+1] ← key

What to watch

  • The left prefix is kept sorted.
  • The key moves into its correct position.
  • The while loop shifts larger values.

Correctness idea

Loop invariant for Insertion Sort

Ask Students
Before iteration j, what should be true about A[0..j−1]?
↻
Suggested answer
A[0..j−1] contains the original first j elements, but in sorted order.
This states both order and preservation of elements.

Correctness proof

Using initialization, maintenance, termination

Initialization

Before the first iteration, A[0] alone is sorted.

Maintenance

The while loop shifts larger elements right and inserts key in the proper position.

Termination

When j = n, A[0..n−1] is sorted. That is the required post-condition.

Interactive activity

Which statements actually support the proof?

Select statements that are logically useful for correctness.

A proof needs statements that connect the algorithm’s actions to the post-condition.
Stress that correctness proof is about meaning, not syntax. A loop existing is not itself proof.
Initial complexity view

How much work does Insertion Sort do?

Best case

Array already sorted.

Θ(n)

Each key is checked quickly.

Worst case

Array reverse sorted.

Θ(n²)

Each key shifts many earlier elements.

Space

Sorts inside the same array.

Θ(1)

Only a few extra variables.

Interactive estimation

Why can the worst case become quadratic?

For a reverse-sorted array, element j may shift across j earlier elements.

Total worst-case shifts are about n(n−1)/2.

Why does the left side remain sorted?

Answer

↻

In reverse order, many elements are shifted repeatedly; the total shifts grow like 1+2+...+(n−1).

Session 6

Correctness of Recursive Algorithms

Loop invariants prove iterative algorithms. Mathematical induction proves recursive algorithms.

Ask: “What is the smallest case the recursive algorithm knows how to solve directly?” That question leads to base case.
Recursive thinking

Recursive algorithms solve a problem by solving smaller versions

🧩
Break downExpress the problem using smaller instances.
🛑
Base caseStop at a directly solvable case.
↩️
CombineUse smaller answers to build the original answer.
Interactive classification

Classify the recursive components

Select a statement to classify it.
Common misconception: a recursive call must reduce the problem size. Calling the same problem again does not make progress.
Ask students

What goes wrong without a base case?

Prediction
A recursive algorithm calls itself but never reaches a smallest case. What happens?
↻
Suggested answer
It does not terminate normally. The call stack keeps growing until resources are exhausted or the program fails.
↻
Example

Recursive Sum

SUM(A, n) if n = 0: return 0 else: return SUM(A, n-1) + A[n-1]

Meaning

To sum n elements, first sum the first n−1 elements, then add the last element.

Base case

The sum of zero elements is 0.

Interactive call tree

Build the recursive call chain

Reasoning

Press Expand next call.

Each call should reduce n until the base case is reached.
This slide helps students visually distinguish recursion depth from loop iterations.

Mathematical induction

Correctness proof pattern for recursion

1️⃣
Base caseProve correctness for the smallest input.
2️⃣
Inductive hypothesisAssume the recursive call is correct for smaller input.
3️⃣
Inductive stepUse the smaller correct result to prove the current case.
Interactive proof construction

Build the induction proof in order

1234

Expected order: base case, inductive hypothesis, inductive step, conclusion.
Worked correctness argument

Why Recursive Sum is correct

1
Base case:
For n = 0, returning 0 is correct.
2
Inductive hypothesis:
Assume SUM(A,n−1) correctly sums the first n−1 elements.
3
Inductive step:
SUM(A,n) returns SUM(A,n−1)+A[n−1], which is the sum of the first n elements.
Compare the tools

Loop invariants and induction are related

AspectLoop InvariantInduction for Recursion
