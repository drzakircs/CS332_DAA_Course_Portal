Core distinction

Problem ≠ Algorithm

🎯

Computational Problem

A specification of what output is required for valid inputs.

Example: Given a list of numbers, return the largest value.

🧭

Algorithm

A finite, precise procedure for transforming the input into the required output.

Example: Scan the list and maintain the largest value seen so far.

Concept of algorithm

An algorithm is a finite sequence of unambiguous, effective steps that solves a defined problem.

InputData / state
StepsPrecise operations
TerminationFinite execution
OutputRequired result
CorrectnessMeets specification
Characteristics of an algorithm

Six properties to remember

1. Input

Clearly specified inputs.

2. Output

At least one meaningful result.

3. Definiteness

No ambiguous step.

4. Finiteness

Terminates after finite steps.

5. Effectiveness

Each step is executable.

6. Correctness

Matches the problem specification.

Reasoning

↻
Reasoning

↻
Reasoning
Indexing / hashing. Extra preprocessing and memory can make repeated exact-key checks much faster.

Basic issues related to algorithms

Questions that shape the solution

About the input

  • What is the input size?
  • Is the data sorted?
  • Can values repeat?
  • Are there invalid inputs?

About constraints

  • How fast must the answer be?
  • How much memory is available?
  • Is an approximate answer acceptable?
  • Must the algorithm work online / in real time?

Constraints can change the algorithm

Ask Students
Suppose we must search the same large dataset thousands of times. Would preprocessing the data ever be worth the cost?
↻
Suggested Answer
Yes. If repeated queries are expected, we may spend extra time or memory once—such as sorting or indexing—to make later searches much faster. This is a classic preprocessing trade-off.

Criterion for analyzing algorithms

How do we judge an algorithm in cyber systems?

Correctness

Does it report the required result for valid input?

Example: no false logic in access checks

Time

Can it respond fast enough for live data?

Example: packet inspection latency

Space

How much memory or storage does it need?

Example: hash tables / indexes

Simplicity

Can it be implemented and audited reliably?

Example: policy logic

Scalability

What happens when logs grow from thousands to millions?

Example: SIEM ingestion

Trade-offs

Can memory, preprocessing or approximation improve speed?

Example: Bloom filter idea

Proving correctness of algorithms

A fast wrong answer is still wrong

⚡

Fast but incorrect

Useless for the specified problem.

✅

Correct + efficient

The real target of algorithm design.

Correctness asks whether the algorithm satisfies its specification for every valid input.

Correctness intuition

Testing can find bugs. Proof explains why it must work.

🧪

Testing

Checks selected cases.

  • Useful for implementation
  • Can expose errors
  • Cannot normally cover every possible input
🧠

Correctness argument

Reasons about all valid inputs.

  • Uses specification
  • Uses invariants / induction later
  • Provides a general guarantee
Ask students

Can testing prove correctness?

Ask Students
If an algorithm passes 10,000 test cases, have we proved that it is correct for every valid input?
↻
Suggested Answer
Not necessarily. Tests increase confidence and can reveal defects, but untested cases may still fail. A correctness proof/argument reasons about the complete valid input space.
↻
Interactive activity · Evidence vs guarantee

Test Evidence or Correctness Reasoning?

Statement 1
“It worked on 10,000 random inputs.”
↻
Classification
Testing evidence. Stronger evidence, but still only a finite sample of inputs.
↻
Statement 2
“After every iteration, max is the largest value seen so far.”
↻
Classification
Correctness reasoning. This is an invariant-style statement that supports a general argument.
↻
Statement 3
“I tried the empty case, one element, and several large arrays.”
↻
Classification
Testing evidence. Edge cases are valuable, but they do not cover every valid input.

Pre-condition · Post-condition

Think of an algorithm as a contract

📋
PRE-CONDITION What must be true before execution
→
⚙️
ALGORITHM Transforms the valid input state
→
✅
POST-CONDITION What is guaranteed after execution

Correctness contract: if the pre-condition is true and the algorithm terminates correctly, the post-condition must be true.

Contract example

MAX(A): specification before implementation

Pre-condition

A is a non-empty array of comparable values.

This tells us what inputs the algorithm is allowed to assume.

Post-condition

The returned value belongs to A and is ≥ every element in A.

This states what the algorithm must guarantee.

Ask students

Strong enough specification?

Ask Students
For sorting, is this post-condition enough: “The output has the same length as the input”?
↻
Suggested Answer
No. A correct sorting post-condition should say that the output is a permutation of the input and that the elements are in the required sorted order (e.g., nondecreasing).
↻
Reasoning pattern

Why does MAX(A) work?

Initializemax = first element
Maintainafter each comparison, max is largest seen so far
Terminateall elements have been seen
Concludemax is largest in A

This “initialize–maintain–terminate” pattern prepares students for loop invariants in Week 2.

Ask students

Pre-conditions matter

Ask Students
A threat-intel list is searched using Binary Search. What important pre-condition is required?
↻
Suggested Answer
The list must be sorted according to the same ordering used by the comparisons. Without sorted order, discarding half of the list is not logically justified.
