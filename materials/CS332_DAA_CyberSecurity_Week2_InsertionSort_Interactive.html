Concept first

How does Insertion Sort think?

🃏

1. Keep a sorted prefix

The left part of the array is treated as already sorted.

🔑

2. Pick the next key

Take the next unsorted element and remember its value.

↪️

3. Insert it correctly

Shift larger prefix elements right until the key can be placed.

Key idea: Insertion Sort grows a sorted prefix one element at a time.

Algorithm mechanics

The standard Insertion Sort algorithm

for j = 1 to n−1: key = A[j] i = j − 1 while i ≥ 0 and A[i] > key: A[i+1] = A[i] // shift right i = i − 1 A[i+1] = key // insert key

What each part means

Outer loop: chooses each new key from left to right.

While loop: moves elements that are larger than the key.

Final assignment: places the key into the newly opened position.

It sorts in place: only a few extra variables are needed.

What changes with input order?

Best, typical, and worst behavior

✅

Already sorted

[1,2,3,4,5,6,7]

Each key is compared with its predecessor and immediately stays in place.

Θ(n)

Few comparisons, zero shifts.

🔀

Unsorted / typical

[7,3,8,2,6,4,5]

Some keys move a little; others move across several earlier values.

Θ(n²)

Average work grows quadratically.

↩️

Reverse order

[7,6,5,4,3,2,1]

Every new key is smaller than all earlier elements and moves to the front.

Θ(n²)

Maximum shifts: n(n−1)/2.

Time and space complexity

Best case: already sorted

The while-condition fails after one element comparison for each key.

(n−1) comparisons → Θ(n)

For n=7: 6 element comparisons and 0 shifts.

Worst case: reverse sorted

For key j, all j earlier elements are larger and shift right.

1+2+…+(n−1)=n(n−1)/2

Quadratic comparisons and quadratic shifts → Θ(n²).

What does O(1) auxiliary space mean?

Only a few extra variables such as key, i, and j are needed; extra working memory does not grow with n.

Do not confuse this with input storage: the array itself occupies Θ(n) memory. Auxiliary space measures extra working memory.

Algorithm characteristics

Important properties

📦

In-place

Uses O(1) auxiliary space.

🤝

Stable

Equal keys keep their original relative order when only strictly larger values are shifted.

📈

Adaptive

Already or nearly sorted data requires fewer shifts.

🧩

Good for small inputs

Simple and often efficient when n is small.

Practical intuition: asymptotic worst-case performance is quadratic, but actual work can be much smaller when the array is close to sorted.

Why is it correct?

The Insertion Sort loop invariant

Invariant: Before each outer-loop iteration with index j, A[0…j−1] is sorted and contains exactly the same elements that originally occupied A[0…j−1].

🚦
InitializationBefore the first iteration, the prefix has one element. A one-element array is sorted.
→
🔁
MaintenanceShift larger prefix elements right, insert the key, and the larger prefix remains sorted.
→
🏁
TerminationWhen j=n, the sorted prefix is the entire array. Therefore the whole array is sorted.

Challenge C — explain in your own words

Why can Insertion Sort be fast on nearly sorted data even though its average and worst-case complexity are Θ(n²)?

Model answer: when data is nearly sorted, most keys are already near their final positions, so the while loop performs few comparisons and shifts. Actual work can be much less than the quadratic worst case.

Insertion Sort — complete mental model

How it works

Grow a sorted prefix. Pick the next key. Shift larger elements right. Insert the key.

Why cases differ

Running time depends on how far keys must move through the sorted prefix.

Complexities

Best: Θ(n)
Average: Θ(n²)
Worst: Θ(n²)
Auxiliary space: O(1)

Correctness

The sorted-prefix invariant is initialized, maintained, and then used at termination.

Properties

In-place, stable in the standard form, and adaptive to nearly sorted input.

When it shines

Small inputs and data already close to sorted.

Mastery check: If you can explain why reverse order creates 1+2+…+(n−1) shifts and why the invariant proves the prefix stays sorted, you understand the core of Insertion Sort.
